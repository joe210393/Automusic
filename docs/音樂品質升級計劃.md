# 音樂品質升級：修改計劃與路徑

**依據：** ACE-Step 1.5 官方建議＋既有「蘇澳拾音」架構盤點＋使用者修正優先序  
**原則：** 不急著換掉整套引擎；先讓 ACE 企劃／LM／shift／XL 發揮，再談 Music Director、2 選 1、母帶  
**現況預設：** `acestep-v15-turbo`、`inference_steps=8`、`duration≈45s`、`batch_size=1`、輸出 MP3、**未傳 `shift`**  
**文件狀態：** 計劃與路徑（本階段先定路線；實作依 Phase 分批開工）

---

## 0. 核心觀念修正（相對舊文件）

| 舊判斷 | 修正後 |
|--------|--------|
| 優先把 steps 8→16/24 | **Turbo 官方建議仍是 8 steps**；硬拉 steps 不一定變好 |
| 品質槓桿 ≈ steps | 優先：**完整 caption 企劃、`shift=3.0`、5Hz LM 真有載入、再 XL** |
| 90 秒拉長 | **維持 45 秒**（已驗證 90s 變難聽） |
| 急著換 MiniMax | **最後才考慮**；先 ACE 同家族升級 |

目標聽感：

> 樂器更真、旋律更自然、整首像製作過的歌，而不是「AI 在唱一段伴奏」。

---

## 1. 目標架構（目標態，非一次做完）

```text
現場聲音 ─分析───┬── BPM / Key / contour / density / motif
                 │
在地內容 ─────────┤── 路線／感覺／故事
                 ▼
          MUSIC DIRECTOR（音樂導演層）
                 │
     ┌───────────┼───────────┐
     ▼           ▼           ▼
  作詞優化     作曲規則      編曲企劃 Caption
 Lyrics+     Melody       Production brief
 Prosody     Planner
     │           │           │
     └───────────┼───────────┘
                 ▼
         ACE-Step 1.5
         (thinking + LM codes → DiT)
         shift / model / batch
                 │
           2 candidates
                 │
         WAV/FLAC → Master → MP3
                 ▼
            旅遊紀念歌
```

與現況差距：現在是「分析→短 prompt→ACE 一次抽 seed」；目標是「導演層先企劃，再生成、再挑、再母帶」。

---

## 2. 開發路線總覽（V1→V4）

```text
V1  企劃餵完整 + Turbo 正確參數 + LM 實核 + WAV + 2 seeds     ← 今天最該做
V2  作曲／作詞規則（Hook、音域、短句、蘇澳 DNA）               ← 產品差異化
V3  XL turbo →（可選）XL SFT + 更大 LM                       ← 聲音品質上限
V4  母帶鏈（從 lossless）                                      ← 最後拋光
```

**不在前三波：** 環境聲硬疊成品、盲目加長秒數、整套換 MiniMax（僅當 V3 仍不夠時旁路評估）。

---

## 3. Phase 明細與程式路徑

### Phase V1 — 今天最該測／改（預期 1～3 天工程＋聽感 A/B）

#### V1.1 確認 5Hz LM 真的在工作（阻塞項）

**目標：** `thinking=true` 不只是參數，而是「LM 載入 → 產 audio codes → DiT 使用」。

| 動作 | 說明 |
|------|------|
| 檢查 ACE UI／API 健康 | LM 選項：No LM / 0.6B / 1.7B / 4B；確認非 No LM |
| Automusic 側 log | finalize 時記錄 `thinking`、回傳是否含 LM／codes 相關欄位 |
| 對聽 | 同 caption：thinking 開 vs 關（若可關）各 3～5 首 |

**程式觸點：**
- `app/voice/acestep.py`（請求體已有 `thinking`；補 stats／log）
- 本機 ACE LaunchAgent／設定（載入哪個 LM）
- `docs/AUTOSTART.md` 補「LM 必須載入」檢查項

**完成定義：** 健康檢查或日誌可證明 LM 已載；關閉 LM 時聽感可對照差異。

---

#### V1.2 傳入官方建議的 Turbo 參數：`shift=3.0`

**現況缺口：** 客戶端**未送 `shift`**，可能落在預設 1.0 軌跡。

| 參數 | 建議（Turbo） |
|------|----------------|
| `inference_steps` | **維持 8** |
| `shift` | **3.0**（環境變數可覆寫） |
| `guidance_scale` | Turbo 上 CFG 行為特殊；勿把希望押在猛拉 CFG |
| `duration` | **45** |

**程式觸點：**
- `app/voice/acestep.py`：`body["shift"] = float(os.getenv("ACESTEP_SHIFT", "3.0"))`
- metering／stats 一併記錄 `shift`

**A/B 矩陣（固定歌詞／caption／seed 策略）：**

| 編號 | Model | Steps | Shift |
|------|--------|------:|------:|
| A | turbo（現況） | 8 | 未設／預設 |
| B | turbo | 8 | **3.0** |
| C | xl-turbo | 8 | 官方建議 |
| D | xl-sft | ~50 | 依官方 | ← 可放到 V3，V1 可先做 A/B |

---

#### V1.3 Caption／Prompt →「編曲企劃」而非標籤堆疊

**現況：** 歌手模板 + 人聲清楚 + style + material 短句。  
**目標：** genre／mood／instrumentation／段落動態／演奏方式／混音。

**建議新增模組（可先純函式）：**

```text
app/voice/music_director.py   # 或 app/music/director.py
  build_production_caption(meta) -> str
```

輸入：`engine_style`、`ai_singer_id`、`material`、`bpm`、`key`、路線／感覺（可選）  
輸出：英文（或中英）**完整 production caption** → 填入 ACE `prompt`/`caption`

範本結構（示意）：

```text
[genre + region] Taiwanese indie travel pop, …
[vocal] warm natural female vocal, intimate …
[tempo/key] 92 BPM, G major, …
[melody intent] catchy pentatonic-inspired hook, small intervals, …
[instruments + performance] finger-picked acoustic guitar, soft fret noise, …
[arrangement arc] verse sparse → chorus wider drums …
[humanization] natural timing, slight imperfections, …
[mix] vocal forward, controlled low end, radio-ready but not over-compressed
[negative] no synthetic EDM textures, …
```

**程式觸點：**
- `app/voice/acestep.py` → `build_prompt(...)` 改呼叫 director，或逐步替換
- 感覺卡／路線可映射「蘇澳 DNA」預設樂器組（先表驅動）

**完成定義：** 同一旅程 meta 產出的 caption 長度與資訊密度達企劃級；A/B 對聽優於舊短 prompt。

---

#### V1.4 輸出改為 lossless 再轉 MP3（V1 可先只改「生成格式」）

```text
ACE → WAV/FLAC（旅程暫存）→（V4 再 master）→ final.mp3
```

V1 最小：`audio_format=wav`（或 flac）下載後再 `ffmpeg`／既有壓縮成 mp3 給下載。  
避免：MP3 → 再 EQ。

**程式觸點：**
- `app/voice/acestep.py`（format）
- `app/journey/service.py` `run_finalize_ai`（轉碼步驟）
- 可重用 `compress_to_mp3`（`app/main.py` 既有）

---

#### V1.5 一次 2 seeds（batch_size=2）— 產品幾乎必做

```text
同 lyrics + caption + bpm + key
    → batch_size=2
    → song A / song B
    → 遊客選一首（或自動先播 A，可切 B）
```

**程式觸點：**
- `app/voice/acestep.py`：解析 batch 多檔、回傳 seeds
- `app/journey/service.py`：存 `final_a`/`final_b` 或 `candidates[]`
- `app/tourist/`：結果頁／finalize 後「選這一首」
- TOKEN：可定「一次 finalize＝1 點含兩版」或「兩版各計」— 產品決策

**完成定義：** 同一請求可聽兩版並選定寫入 `final_file`。

---

### Phase V2 — 作曲／作詞規則（產品差異化）

#### V2.1 Lyric Prosody Optimizer

```text
LM 故事歌詞 → 檢查句長／行數／hook → 短句化 → 再送 ACE
```

結構建議（45 秒）：

```text
[Intro] 短
[Verse] 4 lines
[Pre-Chorus] 2 lines
[Chorus] 4 lines
[Outro] 短
```

**程式觸點：**
- `app/lyrics/` 新增 optimizer 或 post-process
- `_generate_lyrics`／`format_lyrics` 對齊新結構標籤

#### V2.2 Melody Planner（文字層「作曲邏輯」先於 ACE）

現況問題：`notes` 算出來了，但 ACE **不照 MIDI 唱**，只吃文字。

V2 不做「強制 MIDI conditioning」（除非 ACE 後續 API 支援 cover／lego），先做：

```text
分析結果 → Melody brief（音域、級進、hook、主歌／副歌輪廓）
         → 寫進 caption／獨立 melody 欄（若 API 有）
```

規則例：主歌 ≤7 度級進；副歌抬高、hook 2～4 音重複、收在 tonic。

**程式觸點：**
- `app/melody/from_audio.py` 輸出擴充
- `music_director` 合併 melody brief

#### V2.3 蘇澳 DNA 表（內容可複製）

| 路線 | 傾向 |
|------|------|
| 南方澳 | 較慢、民謠、木吉他、偏低音域 |
| 冷泉 | 清爽 percussion、major pentatonic、輕跳躍 |
| 預設蘇澳 | 五聲傾向、上行 hook、明亮 major |

落地：`suao.json` 或 `theory`／director 對照表（可後台編）。

---

### Phase V3 — 模型升級（同家族）

| 階段 | Model | Steps | 條件 |
|------|--------|------:|------|
| V3.1 | `acestep-v15-xl-turbo` | 8 | VRAM 夠（官方 ≥12GB offload，建議更高） |
| V3.2 | LM 1.7B → **4B**（Composition／Copy Melody Strong） | — | 與 thinking 一併 |
| V3.3（可選） | `acestep-v15-xl-sft` | ~50 | 願意等；非即時場次 |

**程式觸點：** `ACESTEP_MODEL` 環境變數／LaunchAgent；健康檢查顯示當前 model＋LM。

**決策門檻：** V1 聽感仍明顯「伴奏感」→ 才上 XL；勿與 V1 caption 改革混在同一天無法归因。

---

### Phase V4 — 母帶（最後）

```text
WAV/FLAC
 → high-pass / corrective EQ
 → gentle compressor
 → subtle saturation（可選）
 → limiter
 → -14～-12 LUFS
 → MP3
```

**程式觸點：** 新 `app/audio/mastering.py` 或 ffmpeg 鏈；僅處理選定 candidate。

## 5. 風險與依賴

| 風險 | 緩解 |
|------|------|
| LM 未載卻以為 thinking 有用 | Sprint 1 先做實核，否則後面 A/B 無效 |
| Caption 過長／風格衝突 | 依官方：避免互相矛盾的標籤；衝突改「時間軸演進」 |
| batch=2 記憶體／時間翻倍 | 先本機測；場次可改「預設一版、付費再出第二版」 |
| XL VRAM 不足 | 維持 turbo；勿強上拖垮場次 |
| notes 與最終旋律仍脫鉤 | V2 誠實：brief 影響 caption；完整「照譜唱」需另評估 ACE 編輯能力 |

## 7. 成功指標（聽感／產品）

| 指標 | 作法 |
|------|------|

---

### 關於「清亮比較好聽」

不完全是錯覺。人耳對**清晰人聲、高頻存在感、人聲靠前**很敏感，常被聽成「比較像製作過的歌」。Sprint 3 已把 caption／混音描述往這個方向調；歌手選「明亮清透」通常也最貼這個偏好。
