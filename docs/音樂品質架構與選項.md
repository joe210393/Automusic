## 一、整體系統架構（與「好聽」有關的部分）

```text
┌─────────────────────────────────────────────────────────────────┐
│ 遊客端 Zeabur（或本機 :8080）                                     │
│  FastAPI + 觀光旅程 UI                                            │
└───────────────┬─────────────────────────────────────────────────┘
                │ 若雲端：ngrok → 本機 Mac
                ▼
┌─────────────────────────────────────────────────────────────────┐
│ 本機 Mac（LaunchAgent，與 Cursor 無關）                            │
│  :8080  uvicorn → Automusic（旅程／內容／帳號／後台）               │
│  :8001  ACE-Step API（最終 AI 整曲）                               │
│  :1234  LM Studio（作詞；可選）                                    │
│  FluidSynth + SoundFont（真實樂器「預覽」伴奏）                      │
│  DiffSinger / Seed-VC（「我的聲音版」路徑；非 AI 成品主路徑）         │
└─────────────────────────────────────────────────────────────────┘
```

**重點：** 遊客覺得「好不好聽」的最終判決，幾乎都在 **ACE-Step 整曲成品**；前面的錄音、作詞、SoundFont 預覽是素材與草稿。

## 二、一趟旅程的音樂資料流（逐步）

| 步驟 | 做什麼 | 產出 | 影響「好聽」的程度 |
|------|--------|------|-------------------|
| 1. 選路線＋現場錄音 | 上傳環境聲 | `sounds[]` | **間接**：只當旋律素材，不混進成品原音 |
| 2. 關鍵字／故事 | 遊客輸入 | `keywords` 等 | **中**：決定歌詞內容與情緒 |
| 3. 感覺卡 | 觀光語意 → `engineStyle` | 如 pop / folk / auto | **中**：影響旋律風格與 ACE prompt 風格字 |
| 4. 創作 compose | 聲音分析 → 旋律 notes／BPM／Key／material | `notes`, `bpm`, `key`, `sound_trace` | **中**：參數會傳給 ACE；旋律線本身不直接當最終音訊 |
| 5. 歌詞 | LM Studio（失敗則模板） | `lyrics` verse/chorus | **高**：歌詞好壞、結構標籤影響 ACE 演唱 |
| 6. 真實樂器預覽 | MIDI + FluidSynth | `preview_file` | **低（對最終）**：聽感常與成品差很大，易誤判 |
| 7. 選 AI 歌手 | 模板 id | `ai_singer_id` | **高**：決定人聲氣質描述（寫進 prompt） |
| 8. Finalize AI | **ACE-Step** text+lyrics→整曲 MP3 | `final.mp3` | **極高**：整體樂感、編曲、混音感都在這裡 |
| 9.（可選）我的聲音版 | 編曲＋聲紋轉換 | `final_voice_file` | 另一條產品線，與 AI 版好聽度分開評估 |

### 2.1 最終成品（ACE）實際吃什麼

```text
輸入：
  - prompt / caption：歌手模板句 + 人聲要清楚 + engine_style + 歌名
                   + material（明暗／輪廓／主音／能量）簡述
  - lyrics：格式化後的 [Intro][Verse][Chorus][Chorus]
  - bpm、key_scale
  - audio_duration ≈ 45
  - model：acestep-v15-turbo（預設）
  - inference_steps：目前約 8（偏快）
  - thinking：預設開（需 ACE 端有載 LM）

輸出：
  - final.mp3（生成式整曲：人聲＋伴奏一次完成）
```

**沒有做的事（刻意／現況）：**
- 不把海浪／泉水原音當背景床疊進 ACE 成品（避免吵雜）
- 不用 SoundFont 軌當最終成品
- 尚未接 MiniMax Music 3 或其他商用 API

## 三、品質瓶頸地圖（為什麼跟 Suno 差一截）

| 層級 | 現況 | 結果 |
|------|------|------|
| **生成模型** | ACE-Step turbo、本機快推 | 人聲可用，編曲／製作感弱於 Suno／Music 3 級 |
| **生成設定** | 短曲 45s、steps 少 | 穩定、快；拉太長（90s）曾明顯變難聽 |
| **Prompt** | 偏「人聲清楚＋旅行 pop」 | 缺少 Suno 式長篇製作描述（鼓、貝斯、chorus 爆開等） |
| **候選** | 一次一版 | 運氣成分大，沒有「兩首挑好聽的」 |
| **後製** | 幾乎無 master | 響度、EQ、限幅未統一 |
| **預覽 vs 成品** | 兩套引擎 | 旅人用預覽期待成品 → 落差大 |
| **聲音推導** | 分析→參數／說明**有**；聽感因果**弱** | 產品誠實，但「好聽」仍靠 ACE |

## 四、若要「更好聽」：可做選項架構（尚未實作）

以下依 **投入／風險／預期聽感提升** 分層。**先寫架構，不改碼。**

### A. 同引擎調參（ACE-Step）— 改動最小

> **已修正：** Turbo 官方建議 **`inference_steps=8` + `shift=3.0`**。把 8 拉到 16/24 **不是**第一優先。詳見升級計劃 V1。

```text
[旅程 finalize]
      │
      ├─ duration_sec     （維持 45；勿再盲目加長）
      ├─ inference_steps  （Turbo 維持 8）
      ├─ shift            （Turbo → 3.0；現況未傳，優先補）
      ├─ thinking + 5Hz LM（必須實核有載入，非僅參數）
      ├─ model            （先 turbo 調通；再試 xl-turbo / xl-sft）
      ├─ prompt/caption   （完整編曲企劃 ≫ 短標籤）
      └─ batch_size       （2 seeds 挑一）
```

| 項目 | 預期 | 風險 |
|------|------|------|
| `shift=3.0` | 結構／語意較清楚（官方 turbo 建議） | 需 A/B 確認預設是否已是 3 |
| 製作向／編曲 caption | 整體「比較像成品」 | 風格衝突會變怪；需表驅動 |
| 確認 thinking＋本機 LM | 旋律／段落企劃層 | 未載 LM＝白開 thinking |
| steps 8→16/24 | **非 turbo 首選** | 更慢且未必更好 |
| 換 xl-turbo／xl-sft | 音質上限 | VRAM／時間 |

---

### B. 產品流程槓桿（不換模型）

```text
一次生成 ──► 兩版候選（不同 seed）──► 遊客挑好聽的
                 │
                 └─ 可選：不滿意「再生成一次」（扣 TOKEN）
```

| 項目 | 預期 | 風險 |
|------|------|------|
| 2 選 1 | 體感品質上升很快（Suno 黏著關鍵） | 時間×2、成本×2 |
| 弱化／改標預覽 | 減少「預覽好聽成品爛」落差 | 少了真實樂器體驗賣點 |
| 歌詞品質關卡 | 差詞直接拖垮演唱 | 要 UX 允許重寫詞 |

---

### C. 後製母帶（ACE 出檔後）

```text
final_raw.mp3 → [響度正規化 / 輕壓縮 / EQ / 限幅] → final.mp3
```

| 項目 | 預期 | 風險 |
|------|------|------|
| Loudness（如 -14 LUFS） | 「比較大聲、比較能播」 | 不解決編曲空洞 |
| 輕 master 鏈 | 一點點質感 | 過度處理會糊 |

**適合：** 低成本讓分享檔「比較能聽」；無法單獨追上 Suno。

---

### D. 換／加生成引擎（聽感決定性最大，工程較大）

```text
                    ┌─ ACE-Step（現況，預設）
MUSIC_ENGINE ───────┼─ MiniMax Music 3（ComfyUI／本機，長 caption）
                    └─（未來）其他開源／API
```

| 引擎 | 預期聽感 | 代價 |
|------|----------|------|
| **維持 ACE＋調參** | 中幅改善 | 低 |
| **MiniMax Music 3** | 可能接近「Suno 級背景／製作感」 | Comfy、VRAM、長 Style Prompt、授權與佇列 |
| **商用 API** | 最快到位 | 成本、資料出境、可複製／地端論述變弱 |

**接入架構構想（未做）：**
- `run_finalize_ai` 只依賴 `generate_to_file(...)` 介面  
- 底下可插拔 `acestep` / `music3`  
- 共用：歌詞、感覺、material→**自動擴寫成長製作 caption**（Music 3 幾乎必需）

---

### E. 「聲音推導」與好聽如何並存（產品架構）

```text
現場錄音 ──分析──► BPM / Key / 明暗 / 輪廓 / 動機
                      │
                      ├─► 寫進 melody notes（預覽用）
                      ├─► 寫進 sound_trace（給旅人看）
                      └─► 寫進 ACE／Music3 prompt（影響生成語氣）
                          
現場原音 ──✗──► 不直接當最終混音床（避免吵）
```

更好聽 **不必** 犧牲「有收音／沒收音不一樣」的說明；但要接受：  
**好聽主要靠生成引擎，辨識度靠參數＋文案＋歌詞。**
